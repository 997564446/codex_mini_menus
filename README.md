# 今儿吃啥捏

面向单个家庭的原生微信点餐小程序：一名厨师维护菜品库存、每周三餐菜单、成员和订单，多名食客按日期及早中晚餐点餐。当前界面只展示一个家庭，但所有核心数据都带 `familyId`，可在后续扩展多家庭入口。

## 已实现

- 一次性口令认领唯一厨师，事务防止并发产生第二名厨师；
- 邀请码、分享入口、小程序码、食客申请、审批、停用与恢复；
- 自动初始化 71 道带单价和库存的默认菜品及“不要主食”，厨师可在未分类新增或删除菜品；
- 自定义分类支持拖动排序，“主食”和“未分类”固定在底部；
- 固定周一至周日的早餐、中餐、晚餐菜单，厨师可分别安排菜品；
- 已保存的早餐、中餐或晚餐菜单可批量同步到厨师勾选的其他星期；
- 有限库存下单扣减、改单按差额调整、取消归还，库存为 0 时不可选择；
- 每人每天每餐一单、菜品备注、整单备注、截止前加菜和取消；
- 最多提前 2 天下单，早餐、中餐、晚餐分别在当天 9、14、21 点截止；
- 厨房按日期聚合人数、总份数和备注，支持逐单与批量推进；
- `pending → confirmed → cooking → ready → completed` 状态机与取消原因；
- 下单幂等键、版本号并发控制、订单快照、服务端角色和家庭隔离；
- 当天订单即时通知，提前订单在用餐当天 6、10、17 点提醒厨师；订阅消息失败不影响订单。

## 本地检查

需要 Node.js 18 或更高版本，无需安装第三方本地依赖：

```bash
npm test
npm run check
```

## 导入与部署

1. 在微信公众平台注册小程序，取得正式 `AppID`，用微信开发者工具导入仓库根目录。
2. 将 `project.config.json` 中的 `appid` 从 `touristappid` 换成正式 `AppID`。
3. 开通云开发环境，把环境 ID 填入 `miniprogram/config/env.js` 的 `cloudEnvId`。
4. 在云开发控制台创建 [数据库安全配置](docs/database-security.md) 中的 11 个集合，并禁止客户端直接读写。
5. 按 [云数据库索引](docs/database-indexes.md) 建立普通和唯一索引。
6. 运行初始化摘要命令，把输出添加为 `system_config/global` 文档。
7. 云函数运行时选择 Node.js 16 或更高版本；在开发者工具中分别右键 `identity`、`family`、`menu`、`order`，选择“上传并部署：云端安装依赖”。随后右键 `order` 选择“上传触发器”，启用提前订单提醒。
8. 如需微信新订单提醒，按 [隐私与订阅消息配置](docs/privacy-and-message.md) 申请模板并填写模板 ID。
9. 使用厨师微信打开小程序，输入一次性口令认领家庭；随后生成邀请码邀请家人。
10. 提交审核前按 [真机验收清单](docs/acceptance-checklist.md) 用三个账号完整走查。

使用 `touristappid` 导入时，小程序会进入只读预览状态并展示部署引导，不连接云函数。完整身份、菜单和订单流程必须换成正式或测试 `AppID` 后验收。

## 项目结构

```text
miniprogram/              原生微信小程序页面、动态底部导航与客户端工具
cloudfunctions/identity  登录会话、厨师认领、资料与订阅授权
cloudfunctions/family    邀请、申请、审批、成员与小程序码
cloudfunctions/menu      默认菜品、分类、库存和星期菜单
cloudfunctions/order     下单、快照、状态机、厨房聚合与通知
docs/                    上线配置、索引、安全、隐私和验收资料
tests/                   可在本地运行的核心业务规则测试
```

各云函数的动作、参数与权限见 [云函数接口文档](docs/api.md)。

## 上线前仍需提供

代码不会伪造微信平台凭据。正式上线前必须由小程序管理员提供并配置：正式 `AppID`、生产云环境 ID、厨师初始化口令、订阅消息模板 ID，以及微信公众平台隐私保护指引。本项目没有微信支付、退款或结算功能。
